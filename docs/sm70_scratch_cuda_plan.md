# 从 0 写 CUDA 的方向总结（脱离现有方案）

日期：2026-09-17
对象：Qwen3.8-27B-QUASAR-NVFP4 / 4×V100-SXM2-16GB / PCIe / TP4
模型形状（引自 `config.json` 的 `text_config`）：hidden 5120，**head_dim 256**，
24 个注意力头对 4 个 KV 头（GQA，就是 4 个 KV 头伺候 24 个提问头），64 层。

本文不再沿用之前的方案清单，改从一个问题出发：**180K prefill 的每一秒设备时间
到底去哪了，哪些池离自己的物理上限最远。**

---

## 0. 结论先行

1. **最值得从 0 写的是 prefill 的 NVFP4 融合矩阵乘**，不是通信、不是注意力。
   它是最大的时间池（52.4 s/卡，占 44%），而且是**离本机实测上限最远**的一个
   （跑在本机墙的 44%–59%，而同机纯 FP16 矩阵乘能到 103 TFLOPS）。
2. **注意力（方向 2）是第二位**，但它的对象是 decode 侧（180K 时占 32.9%），
   而且 `head_dim=256` 意味着**所有现成 FlashAttention 都不适用**（上游 FA2 要
   SM80+，FA-Volta 只支持 64/128），所以它天然就是"从 0 写"。
3. **把卡间求和藏进计算（方向 3）**时间池第二大（35.8 s），但同一台机器上
   三次实现尝试全部实测为负，而且"主机阻塞是关键路径"这个假设已被引擎自报数据
   证伪。它只剩一种没试过的形态。
4. decode 侧的逐 token 矩阵乘（GEMV）**不要写**：已到本机显存带宽屋顶的 92.4%。

---

## 1. 事实基础：180K prefill 的时间去哪了（全部实测）

引自 审计 [54]（nsys 轨迹，device 0，118.2 s 窗口，设备忙 91.8%）：

| 池 | 忙时 | 占比 |
|---|---:|---:|
| NVFP4 矩阵乘（`Kernel2`，即 QPN2/TurboMind 那条路） | 39.8 s | 36.7% |
| 卡间求和（NCCL all-reduce） | 35.8 s | 33.0% |
| 注意力（softmax + block update + head gather） | 13.4 s | 12.4% |
| FP16 矩阵乘（volta_s884gemm 系） | 12.6 s | 10.7% |
| NVFP4 解量化 | 2.1 s | 1.8% |

矩阵乘整条路（NVFP4 + FP16 + 解量化）合计 **52.4 s**。

**离上限多远（实测 + 引自的计算）：**

- 本机墙：独立 cuBLAS FP16 tensor-op 在 M=4096/K=5120 扫 N=512..32768，
  **78.5–104 TFLOPS，约 103 的平台**（引自 审计 [55]，50 次平均）。
- 引擎矩阵乘整条路 **45.6 TFLOPS**，`Kernel2` 单独 **61.0 TFLOPS**
  （引自 审计 [58]，按真实发射形状算的 FLOPs）。
- 也就是整条路在本机墙的 **44%**，单独那个 NVFP4 矩阵乘在 **59%**。
- 排除掉的三个解释（全部实测）：不是形状碎片化（44 chunk × 64 层 × 10 个形状，
  每次都是完整投影）；不是功耗墙（同形状独立跑 97.3 TFLOPS / 1432 MHz / 243 W，
  无降频）；不是 cuBLAS 没开 tensor-op（开关打开后逐项内核数相同，收益 0）。

## 4. 排序理由与第一步

**为什么 #1 排第一**：它是最大的池（52.4 s），而且离物理上限最远（44%–59%）。
相比之下 #3 的池虽然也不小（35.8 s），但同一台机器上三次实现尝试全部实测为负，
继续投入的边际风险高；#1 没有任何一次实测碰过它——之前排除的三个解释
（碎片化、功耗、cuBLAS 开关）全部打在别的假设上。

**#2 排第二**是因为它有明确的实测差距（1.55 倍于地板）且随上下文长度增长
（8K 5.7% → 80K 20.0% → 180K 32.9%，[18]），长上下文正是我们的目标负载。

**第一步（#1）**：写一个最小验证版，只针对 10 个真实形状里最大的那一个，
在独立测试里量"每秒字节数 / TFLOPS"对齐本机墙 103 的百分比。
及格线：**到墙的 60%**（好内核在混合输入下的典型水位，引自 [55] 的说法）。
达不到就停下来报告，不带病接入引擎。
